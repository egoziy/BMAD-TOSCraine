## 7. ⚠ Security-sensitive findings (to be fed into 02_components and 09_open_questions)

1. **DB server & name are exposed in cleartext** in `RTG1-2/RTGApp.exe.config`: `Data Source=192.6.8.52;Initial Catalog=TerminalData`. Authentication is Integrated (Windows), so no password is present, but the host/database is. Confirm whether this server and the one in `00_database_context.txt` (`SQL01`) are aliases for the same box.
2. **UNC log path leaked** in the same config: `\\broadcaST\Logs\RTG\` — discloses an internal server name `broadcaST`.
3. **Hard-coded internal IP in source**: `TOSConsole*/Program.cs` calls `IPAddress.Parse("192.6.1.8")` as the TCP listener bind-address. This IP is the listener server, not the cranes.
4. **`ForkliftApp_TemporaryKey.pfx`** exists in `From TFS/RTG/New Folder/ForkliftApp/ForkliftApp/`. VS's default-generated "TemporaryKey" PFX is usually a dev signing key, but the filename alone cannot confirm that. Treat as a potential secret and confirm (Q-03).
5. No credential values, API keys, hostnames beyond the above, or private certificates were found in the RTG-specific source. I have not exhaustively searched .resx / .resources / binary blobs.

## 8. What this tells us for the next steps

- **Component mapping (1.2) is essentially three .NET Framework 4.8 code bases** plus two .NET 6 maintenance utilities. Listener and Persistence are merged into the same process (`TOSConsole*.exe`).
- **Per-crane differences are real, not cosmetic** — RTG3 is on a separate code branch and has its own DB views. The RTG1-2 vs RTG3 schism is the single biggest risk to "single pane of glass" redesign.
- **DB-side logic is substantial**: 80 stored procedures and 13 views listed at priority 1–3. A large portion of the business rules live in T-SQL, not in the C# code.
- **Configuration is done by filesystem artefacts** (`CHEName.txt`) and hard-coded constants (IPs, ports, CHE IDs in `Program.cs`) — not by proper config files. This will be a deliberate redesign target in Phase 2.
- **`RG_ErrorLog` has 1.6M rows** — Step 1.7 should sample it to understand what errors actually fire in prod.
